# 0037 Declared network rules, and the limits on rules

- A ship that owns labels (a plugin such as squadrons or the trierarch plugin) declares the network rules it needs to core with `fleet.declareNetworkRules` (`labels:define`, also on REST and MCP as a fleet action): its whole list, replacing what it declared before; an empty list withdraws them. Every term of every rule uses a label the caller owns: an exact value's label, and the label of a `*` or `#` term. An unknown id is refused, as its owner cannot be checked. The rules follow 0034's format and selector limits. Each change writes NetworkRulesDeclared (the declaring ship and the number of rules, never the rules).
- Core stores them per declaring ship. They are not in force by being declared: the fleet's networking plugin reads them (`fleet.declaredNetworkRules`, `fleet:network`, each declaring ship with its list) and adds them to argo's rules whenever it supplies the list, so without a networking plugin nothing is in force (0035). Argo's none (all-to-all) stays none: rules only allow, so declared rules add nothing to it. The networking plugin supplies the fleet again when a NetworkRulesDeclared event comes, following the fleet's events.
- A plugin switched off or deleted withdraws its declared rules. Retiring the declaring ship removes them in the same unit of work, with NetworkRulesDeclared of none, as its labels retire with it (0031). The labels a plugin assigned stay when it withdraws.
- Limits, named by every refusal of them (`NETWORK_RULES_MAX`, `DECLARED_NETWORK_RULES_MAX` in common):
  - argo's own rules: at most 200. The fleet holds at most those 200 plus every rule its plugins declared, so the list the networking plugin supplies is checked against 200 plus the declared rules stored then;
  - declared rules: at most 20 per declaring ship.

Why: an owner of a group keeps its own members labelled and its own reach in place, so argo never maintains rules per squadron, per trierarch or per plugin (design on #573). Rules only on labels the declarer owns keep them safe: only it assigns those labels (0031), so its rules reach no ship it did not label. Every rule in force stays visible and supplied by the plugin, with no hidden core exception per plugin. The limits keep each send's check fast; they are a deliberate exception to 0016, for performance, not policy.

Rejected: core merging declared rules into the rules in force itself (the networking plugin supplies every rule in force, 0035); declared rules counting toward argo's 200 (one plugin could crowd argo out); a plugin declaring rules on labels it does not own; a fixed core exception per plugin.
