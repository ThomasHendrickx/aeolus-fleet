# 0060 A2A through the gateway

- **An outside A2A client is added by an approver** on the gateway's page: any actor holding the approving scope (0056) names it and sets its owner and scopes. The gateway commissions an `a2a-client` proxy ship and shows a bearer once. The card declares an HTTP bearer scheme.
- **Cards.** Each card's interface address is `/gw/a2a/<alias>`, the alias the gateway's HMAC of the fleet id and ship id, derived, never looked up. The public card carries no summary and no skills: it names the gateway as provider and states the interface, the bearer scheme and `extendedAgentCard: true`. The extended card carries the ship's statement for that caller, from `discover` as the caller's proxy ship.
- **Finding the ship.** The bearer names the party, so its fleet and its proxy ship. The gateway calls `discover` as that proxy ship, computes the alias of each ship answered and takes the one that matches. No match means unknown or unreachable, and both get the same error. A send goes to that ship by name, as the proxy ship, and core checks the network rules again (0034).
- **Card addresses.** The party's detail on the gateway's page lists the card address of each ship its proxy ship reaches now, from `discover`. The party's owner hands the addresses over.
- **One switch** per fleet covers MCP and A2A parties (0056).
- **The capability called.** An inbound message calls the first capability whose first input mode equals its content type. When none matches, there is no wait and no deadline, and the first reply completes the call.
- **Content type of an inbound message.** One text part travels as its text, with its `mediaType` (`text/plain` when none). One data part travels as JSON, with its `mediaType` (`application/json` when none). Anything else travels as the whole message, as `application/a2a+json`.
- **No cancellation.** `CancelTask` answers `TaskNotCancelableError`. A message with the task's `taskId` that asks to stop is sent to the ship like any follow-up, and the ship decides.
- **Repeatable.** An outside A2A agent is repeatable by default (interop I-7). Any actor holding the approving scope marks it not repeatable, on the party's detail, as MCP tool marks are set.
- **AUTH_REQUIRED** from an outside agent goes back to the sender as a reply carrying that state, then the delivery is handled, and the proxy ship's owner is notified. What notified means waits for the notifications work.
- **The SDK.** The A2A bindings use `@a2a-js/sdk` behind the gateway's ports, pinned, with the gateway's call store in place of the SDK's task store; its A2A client calls outside agents. The A2A endpoints are Fastify routes in `src/adapters/http`, beside `/mcp`, in the same process; the pages stay in Next.js (`web/`), and no Next.js route serves A2A.

Why: an A2A client is software with no browser, so it cannot sign in through OAuth as an MCP client does. Only the ships that can send to a ship, and argo, read its statement (0047). A2A has no registry, and the list follows the rules in force. Approval already gates each party. An A2A message names no skill and standard clients send only standard fields, while a ship that knows nothing of A2A still reads plain text or JSON. Aeolus cannot withdraw a stored message. Nothing is argo's alone (0053). Credentials stay in the vault and never travel in a message. Spec changes land in one dependency, and the SDK serves both verbs of SubscribeToTask. Design: [docs/design/a2a](../design/a2a/README.md).

Rejected: task state in core (the gateway keeps it, 0048, 0001); A2A for person ships, who keep the gateway's MCP tools (0054); gRPC, signed cards and a registry of cards; the SDK's Express integration and Next.js route handlers for A2A.
