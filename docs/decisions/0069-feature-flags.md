# 0069 Feature flags

A fleet's feature flags gate features the app admin offers per fleet. Common names the flags there are, each a key, a name, one line saying what it turns on and the line shown while a fleet uses it; today only `sealing`. Core keeps a row per flag that is on for a fleet in `fleet_feature_flags`, none being off. The installation sets one with `installation.fleets.setFeatureFlag`, writing `FeatureFlagTurnedOn` or `FeatureFlagTurnedOff` in the same transaction, and lists them with `installation.featureFlags.list`; `installation.fleets.create` takes the flags a new fleet comes with on, and `get` and `list` answer each flag on or off and whether it can go off now. Pagasae keeps the defaults for new fleets beside its plugin defaults, so a changed default never reaches a fleet that exists.

A flag cannot go off while the fleet uses its feature: sealing while the fleet is sealing or sealed (`FEATURE_FLAG_IN_USE` with the flag's line, changing nothing). Off, the console shows nothing of the feature, and its procedures are refused `FEATURE_FLAG_OFF`, changing nothing: for sealing `fleet.turnOnSealing`, `fleet.changeCompanyKey`, `fleet.changeRecoveryKey`, `fleet.recoverySet` and `fleet.recoverKeys`; `fleet.sealing` stays a read of where sealing stands. Turning sealing on reads the flag again with its row held, so it cannot go off meanwhile. The console learns the flags that are on from `console.session`: no entry on the Fleet overview and Not found on `/sealing` while sealing's is off. A server without an installation token has no one to set them: each flag has its own value there, sealing on when the server has a KMS (`KMS_REGION`). With a token and no KMS nothing extra: turning sealing on fails at the KMS check.

Why: sealing ships before the ends that wait on its key and hosted Aeolus's KMS, so a fleet must not turn it on before the app admin offers it; the next feature that needs the same gate adds one flag, not another design (Thomas, 30 Oct 2026). Sealed fleets keep sealing (0068): their payloads need their keys and the sealing page.

Rejected: a flag going off for a fleet that uses its feature, stopping only new use or hiding it too; every flag on without a token, or a `FEATURE_FLAGS` setting; defaults in core's installation settings; each feature's own read answering its flag; the flags in the Fleets table's Plugins column; rollout percentages, flags per ship or account, and per-flag UI in Admin.
