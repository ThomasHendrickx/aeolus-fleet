# Decisions

Current state only; history is in git. To change a decision, edit its file and its line here in the same commit. Read this index first; open a file when you need the full rule.

- [0001](0001-ack-on-receipt.md) **Ack on receipt.** Ship acks when it receives; on a pushed ship the hook acks when the message comes into the agent's turn. Aeolus owns distribution, not execution.
- [0002](0002-opaque-ship-secret.md) **Ship secrets and scopes on the server.** Opaque hashed secret, one per ship, used only to register; scopes stored server-side with the ship, never carried by it (the catalogue is 0046).
- [0003](0003-postgres-as-broker.md) **Postgres is the broker.** Commit before OK, `SKIP LOCKED` claims, `NOTIFY` after commit.
- [0004](0004-trpc-single-api.md) **tRPC is the only API door.** REST and MCP map onto the same procedures (ship calls and the fleet actions for ships with fleet scopes), no own logic.
- [0005](0005-prefixed-ids.md) **Prefixed ids.** `<prefix>_<lowercase ULID>`: `flt_ shp_ msg_ dlv_ evt_ lse_ crd_ opr_ ses_ lbl_ lbv_ rfs_`.
- [0006](0006-payload-limit.md) **Payloads max 64 KB.** Carry a reference plus instruction, not content.
- [0007](0007-tenancy.md) **Every record belongs to a fleet.** `fleet_id` everywhere, scoped queries. Only unscoped: secret hash, token hash, operator email lookup, and the installation (0020).
- [0008](0008-packages.md) **Six packages.** core, console, common, squadrons, trierarch-plugin and trierarch (the last three optional), in release trains (0049); infra private.
- [0009](0009-stack.md) **Stack.** Node 26, Fastify, tRPC, Next.js, Prisma, Zod, Vitest, Testcontainers, Playwright.
- [0010](0010-leases-without-heartbeats.md) **Leases until released.** No heartbeats; second claim fails (except `argo` takeover); release and deregister invalidate the secret; location reported on claim; a trierarch's release releases every lease it crewed.
- [0011](0011-release-via-trusted-publishing.md) **Release via trusted publishing.** Only `release.yml` publishes, no tokens, from main or `hotfix/<major>.<minor>.x` for a commit whose CI push run on that branch passed, one version per release train (0049), no second test run, publishing a candidate's tarballs (`candidate.yml`, an Actions artifact) once the walker's `staging-walk` status on the commit passed, or with Thomas's `override_reason`, tags `v<version>` a commit on top of the released one with the plugin's version (off main), creates its GitHub Release with notes from the PRs labelled `<version>`, and commits the plugin's version to main only for a main release.
- [0012](0012-operator-is-a-ship.md) **Operator is the ship `argo`.** Permanent, all scopes, no secret, always shown as crewed; its lease taken only by a console sign-in as argo, by an allowed account's sign-in ticket or argo's own sign-in, naming which in argo's events; one at a time; accounts sign in to the console without a lease, many at once; the fail-safe, never a normal path; plugin pages and other services check a console session with `console.session`, from the forwarded cookie; other kinds in 0044.
- [0013](0013-breaking-changes-before-1-0.md) **Breaking changes before 1.0.0.** Allowed; no compatibility layers.
- [0014](0014-strict-test-driven-development.md) **Strict TDD.** Server and common test first, `(red)` commit then green; push green only.
- [0015](0015-ship-identity-per-conversation.md) **Identity per conversation, per folder with the plugin.** `register` returns a crew token; later calls carry it; MCP connection has no ship credential; the plugin keeps the token per working folder in `~/.aeolus/crews/<harness>/`, outside its data folder, and makes every fleet call through its scripts, so the model never sees it; a chat with no shell crewing an agent ship passes it on `/mcp`, an accepted risk, and a person reaches their person ship through the gateway without one.
- [0016](0016-no-policy.md) **No policy.** Scopes are enforced exactly; Aeolus adds no protective rules. Risk is the operator's call.
- [0017](https://github.com/ThomasHendrickx/aeolus-fleet-squadrons/blob/main/docs/decisions/0017-squadrons-package.md) **Squadrons, a ship of the fleet.** Separate package, own process and database, reaches the fleet only through the public API as its squadrons ship, owned by argo (fleet:read, fleet:commission, fleet:manage, labels:define, labels:assign, fleet:on-behalf, scopes:declare), labelling its squadrons' ships and declaring their reach, manage included, on its own labels; declares `squadrons:form` and `squadrons:scale`, forming by message from any ship holding them, templates granting within the subset rule, limits its configuration; names the forming ship's owner on the squadron's ships; the flagship proxies to the forming ship, then its owner once retired; own pages; reads on behalf of a person's ship; Aeolus knows nothing about squadrons.
- [0018](0018-model-and-harness.md) **Model and harness.** Every send of an agent ship states the session's exact model (argo, person, app and plugin ships state none); the harness is free text with known values, stated when a session crews a ship and read with its location.
- [0019](0019-starting-prompt-presentation.md) **Starting prompt presentation.** Core issues the secret only; the tRPC adapter answers the prompt, one crew line per harness (Claude Code, Codex) and the secret; clients read `secret`, never parse a line.
- [0020](0020-installation.md) **Installation.** One server hosts many fleets for a hosting service; installation procedures on the tRPC router behind an installation token (off without one); request ids on create and delete; an account signs in as argo with a one-time ticket naming it; procedures to end an account's console sign-ins and cut off its tokens; the installation an actor in each fleet with the scopes its jobs need and a built-in manage rule over person ships; limits are configuration (defaults, per-fleet override, fleet cap; unset is none); delete removes every record of the fleet, events included, and keeps only a request hash.
- [0021](0021-squadrons-installation.md) **Squadrons serve many fleets, switched per fleet.** One install, one connection per fleet; a hosting service switches squadrons on or off per fleet with squadrons' own installation token (open and every fleet served without one); off does nothing and keeps everything; delete forgets the fleet in squadrons only.
- [0022](0022-viewer-ship.md) **Viewer ship.** A fleet created with a viewer gets the permanent ship `viewer` (`fleet:read` only, reading every ship through a built-in read rule that `fleet:network` may turn off, receives nothing); viewer tickets start viewer sessions, many at once and holding no lease, 2 hours after last use and 24 at most; `console.session` answers the kind and scopes.
- [0023](0023-notices.md) **Notices.** The installation sets the console's notices (text, links, dismissible, audience `everyone`, `operators`, `viewers` or `accounts`), replacing the list; each console session shows those of its audience above every page and dismisses a dismissible one for itself, an account by its id; a link may sign out first.
- [0024](0024-guide.md) **Guide.** The installation sets one guide (audience, 1 to 10 steps of page, optional anchor, title and text); each console session of its audience keeps its own progress on the server, an account by its id, the guide opens by itself, Skip and Finish hide it for the session, Take the tour opens it again, and a step whose anchor is not on the page shows centred.
- [0025](0025-console-analytics.md) **Console analytics.** Off by default; `AEOLUS_HOSTED_ANALYTICS_*` turn on a server-side adapter (PostHog, fetch only); the browser posts a closed list of events to the web app's own `/api/analytics`, which adds the session kind and an anonymous daily visitor id; no ids, names or cookies.
- [0026](https://github.com/ThomasHendrickx/aeolus-fleet-trierarch/blob/main/docs/decisions/0026-trierarch.md) **Trierarch.** A plain process per machine, crewing a ship of type trierarch with crew:run, a normal ship otherwise, commissioned by the trierarch plugin and set up with init, on a human's computer owned by their account's person ship; it reconciles from the crew requests assigned to it, crewing again a ship released elsewhere from a fresh worktree, writes their status and reports what it can do in its report's details; a spent restart budget writes crashed and reports to the ship's owner, argo as fallback; a session it crews holds no fleet credential, its calls forwarded over a socket of its ship's own with the crew token added, path and size checked, nothing queued; a new settings version (Restart, Edit) crews the ship again in its worktree; saved as crewing before register, so a lost register reply is released and crewed again; never picks, commissions or retires; a removed request is released and confirmed, removing its worktree whatever it holds and telling argo what that discards.
- [0027](0027-crew-settings.md) **Crew settings.** Open standard with a fixed core (optional harness, workspace, optional squadron, optional first prompt, options); without a harness the trierarch crews with its default, the first in its configuration, its options checked against it; each harness's options as a JSON Schema in the trierarch's report, an option it does not declare ignored; no paths or flags; schemas in common; the 0.17 message protocol retired.
- [0028](0028-report-details.md) **Report details.** A report may carry `details`, one JSON object of at most 16 KB stored without meaning on the lease; the crew sets it whole or merge-patches it (RFC 7386), the limit checked on the result; `ShipReported` on any change, carrying the details version; the shape per ship type lives in common.
- [0029](0029-crew-request.md) **Crew request.** Declared crew state on the ship, at most one, standing; settings refused unless they are crew settings of at most 16 KB whose machine labels are label values of the fleet, never acted on by the server, versioned on every request; never argo, the viewer or a retired ship, and a retire removes it; three writers: request (fleet:manage, manage reach), assignment by optimistic claim (crew:assign) to any active ship, no routing, with a reason while unassigned; who crewed it derived from the claimed prompt; status (crew:run, assigned ships only); a give-back by the assigned trierarch while its crew is not final (final from its first working status until the next settings version), recorded until the next settings version; removal releases through an irreversible finalizer; unassigned it is the operator's to-do; crew:assign and crew:run, never one scope crewing any ship.
- [0030](https://github.com/ThomasHendrickx/aeolus-fleet-trierarch-plugin/blob/main/docs/decisions/0030-trierarch-plugin.md) **Trierarch plugin.** The trierarchs' plugin on the server side, optional, its own package and process beside squadrons, a ship of each fleet it serves (fleet:read, fleet:commission, crew:assign, crew:run, labels:define, labels:assign, scopes:declare), owned by argo; placement across people's machines is the organisation's label-based ruleset in the plugin, switched per fleet as squadrons; its own small database holds only each fleet's connection and switch, everything else lives in the fleet; commissions trierarch ships for an actor holding trierarch:join, a scope it declares and enforces, or argo, owned by the adding account's person ship or argo, and gives their starting prompts; labels machines from their reports every trierarch ship `trierarch=machine` and its own `trierarch=plugin`, declaring `trierarch=*` to `trierarch=*`, withdrawn when off or deleted; assigns requests oldest first by optimistic claim to the fitting trierarch with the most room, writing a reason when none fits; places a request given back again without the trierarchs that gave it back; flags a machine silent past a threshold, never moves a final assignment.
- [0031](0031-labels.md) **Labels.** A key with defined values, owned by the actor that defined it (labels:define); a label and each value have an id, kept across changes, and calls take ids (a lookup turns texts into ids); a ship holds a set of value ids, assigned only by the owner (labels:assign), on its own ship and ships it commissioned, labels:any on any within manage reach; a key once per fleet; a carried value or label is never removed or deleted; labels retire with their owner and go with a retired ship; an import of network rules defines the labels it lacks for argo or a definer it picks within manage reach; the fleet list selects by exact matches combined with AND; limits (a-z, 0-9, -, 63 characters; 50 values; 20 values a ship) named by every refusal.
- [0032](0032-clear-request.md) **Clear request.** A kept worktree is cleared by a declared request to its trierarch (fleet:manage, manage reach), naming the worktree by its ship and repository, never a path; one per trierarch, ship and repository, at most 100 pending per trierarch, never withdrawn; read by fleet:read (all) and crew:run (its own); the trierarch removes only a worktree it kept and confirms removed or not-kept; a retired trierarch's requests go.
- [0033](0033-console-logic-on-the-server.md) **Console logic on the server.** Logic (fleet and plugin calls, parsing their answers, checks, typing outside data) runs on the web app's server or behind the API, never in the browser; the browser holds only UI interaction and animations and renders what it is given; reads through route handlers, changes through server functions (which Next.js runs one at a time); which plugins are on or off reaches it only as what a page shows; live form hints stay in the browser on `@aeolus-fleet/common/rules` (no zod, the schemas built on it), the server the authority on submit; zod, plugin clients and plugin answers in no client chunk.
- [0034](0034-network-rules.md) **Network rules.** Scope says what, a rule says where: each rule names send, read or manage (force and discovery ride send, resend read); selectors of label or owner terms (exact, `*`, `#` same value on both sides), matching an account by its token's group values; allow-only, never by type; built-in rules seeded at fleet create and shown first: argo and the owner every verb, an answer to its sender and a connected plugin reading every ship (never off; argo's Connect connects it, a release or retire ends it), the viewer read (turned by its own action, with an event), open every verb exactly while no rules of the fleet's own are applied, the installation managing person ships and what they own (never off); beside them the fleet's own (0035) and the declared ones (0037), merged at each check; sends checked at send time, reads filtered (a message through its sender or recipient, outside read reach name, type and status only; a plugin may read on behalf of a named ship, with that ship's reach), manage, grants and owner changes checked on the target; a refusal stores only its record, read with fleet:explain, and says only "No rule matches" with its rules version; explainReach (fleet:explain) answers per verb naming the exact rule, against the applied rules or the draft, the sender's refusal and discovery none; checks and changes, declarations included, take turns on a per-fleet advisory lock.
- [0035](0035-network-rules-draft-and-apply.md) **The fleet's own rules: drafted, looked at, applied.** In core, the whole list or none for all-to-all, read and changed by any actor holding fleet:network with no manage-reach check; one draft a fleet, saved whole and discarded without moving the version, never checked against; what it gains and loses per verb among the ships the caller reads, and explainReach against it; an apply names the version looked at, refused CONFLICT once the settings moved, else puts the draft in force at the next version and drops it. Export writes the applied rules and their labels as one file by name; import checks it, shows the differences and fills the draft.
- [0037](0037-declared-network-rules.md) **Declared network rules and their limits.** An actor that defined labels declares its whole list of rules (`labels:define`), each naming its verb, every term on a label it owns, unknown ids refused; stored per ship and checked beside the fleet's own, in force at once and moving the version, an empty list or its retirement withdraws them; fleet:network reads them, shown apart on Network, read-only, with who declared them; at most 200 of the fleet's own counted alone, at most 20 declared per ship, named by every refusal.
- [0038](0038-questions.md) **Questions.** A ship asks its owner's ship (argo when argo owns it) with a message of `application/vnd.aeolus.question+json` (its own uuid, title, context, options numbered from 1 with a label and an optional detail, the asker's pick and why); the owner answers through whatever app crews its ship with a reply of `application/vnd.aeolus.answer+json` (the question's uuid, one option and an optional note, or a note alone); open until answered, whatever the delivery's state; a fleet convention in the ship protocol. The asker withdraws one (`application/vnd.aeolus.question-withdrawal+json`) or replaces it (`application/vnd.aeolus.question-replacement+json`); unanswered, it is then stale. The console's questions UI for argo is frozen (0043).
- [0039](https://github.com/ThomasHendrickx/aeolus-fleet-trierarch/blob/main/docs/decisions/0039-container-sessions.md) **Sessions in containers.** A machine's choice in its configuration (host by default), no crew setting or label, stated in the trierarch's details; the `SessionRuntime` port gets a container adapter, one container per ship with tmux inside; rootless Podman on Linux and Colima on macOS behind one adapter, never the runtime's socket inside, hard caps per session; the workspace a per-ship clone with `--reference` and `--dissociate`; no fleet credential in the container (its calls go over the trierarch's socket, 0026); one long-lived model token per machine, no Remote Control, Claude Code only; keys per repository; the image published with the release, another per repository built on it.
- [0040](0040-delivery-protocol.md) **Delivery protocol.** The promise ends at the agent's confirmation. The computer side (trierarch, plugin watcher) push receives: pending to received, no attempt, its own in flight again unchanged (`DeliveryReceived`, marked `again`); the lease is pushed from its first push receive (`LeasePushed`, with the waker it states: trierarch, pluginWatcher, personApp, gateway or adapter) until it ends, and the agent's plain receive then answers nothing; `handed` carries a hand-over number and optionally its channel, a higher one counting one attempt, a repeat no change, the fifth undeliverable; ack takes received or handed; lease end returns both to pending. The hooks report the turn (`turn`, idle or busy at its own time, `TurnReported`), `handled` after a turn that took an acknowledged delivery ended by itself, `handed` with `isOnceMore` once after a died turn (no attempt), `delivery` re-reads an acknowledged, not yet handled delivery of the crew's lease, whole, recording nothing, and `notHandled` when that turn died too, or with a reason for a handed delivery not confirmed that is unsafe to hand again (interop 5.2), which shows in Needs attention with Resend and Dismiss. A forced delivery (messages:force) comes first; the trierarch stops a busy turn and hands it over, a hand-crewed session gets it at its next tool call or Stop (a hand-crewed Codex task at its next idle: force is a best effort, not a promise), and a stopped turn's delivery is handled when the forced turn ends. The fleet runs the 10 and 60 minute clocks of a pushed lease (handed and not confirmed 10 min; pending or received 10 min idle, 60 min busy) and tells argo once per lease and oldest overdue delivery with `DeliveryOverdue` and a Needs attention entry that clears by itself; a person ship runs no clocks.
- [0041](0041-fleet-health.md) **Fleet health.** The installation describes each fleet's health beside its measures: oldest pending, oldest in flight (counted as the overdue clocks count it), no ship can take, needs attention (undeliverable) and overdue, read from delivery states and times in the fleet's one read, no event, its stuck deliveries from 0042's snapshot; times not ages, thresholds the hosting service's; Needs attention lists no ship can take in its own group, no action, clearing by itself; Retire unchanged, a type's pending deliveries wait for a new ship of the type.
- [0042](0042-stuck-deliveries.md) **Stuck deliveries.** One cause each, the first that holds: undeliverable, no ship can take, waiting for crew (a ship awaiting crew, never a person ship, or a type whose every ship that may take it awaits crew), stalled in flight (overdue by the pushed clocks, told or not, or handed on a plain lease whose session was last seen no later than the hand-over, 10 minutes ago or more; never at a person ship); place the ship or the type; read as facts with ages, no thresholds: stuck now by cause and place (count, oldest), stuck per hour over 7 days and acknowledged in 24 h with the median from an hourly cumulative snapshot the 30 second pass closes once per hour under an advisory lock, counted by message parties, reads folding the events after it; the machine behind each ship; not handled is no cause; replaces 0041's ages out of the console.
- [0043](0043-core-surface.md) **Core's surface.** Core is the fleet server, its API and the fleet's admin console, for every Fleet manager its scopes allow and for argo, nothing more; people act as their accounts and reach their person ships through their own app, a chat or the gateway; plugins serve their own pages, checking the actor's scopes (`console.session` for argo or the viewer, the account token for a person); the console's questions UI is frozen and later moves out.
- [0044](0044-ship-kinds.md) **Ship kinds.** operator, viewer, agent, person (a human's ship for messaging and owning, linked to their account, owning itself) and app (an application or outside party); only an agent states a model; person ships commissioned with fleet:person, by the installation for an account; and a ship with fleet:commission and fleet:on-behalf (the gateway) commissions app ships; a person's app holds its lease, and a person ship awaiting crew is not stuck.
- [0045](0045-owners.md) **Owners.** Every ship but argo and the viewer has one owner, a person's ship or argo, a person ship owning itself: at commission the commissioning person ship, an account's person ship, or the commissioner's owner, argo by default (plugin and trierarch ships argo's), a plugin with fleet:on-behalf may name the owner of the ship that asked it, or the owner the approver picked for an app ship it commissions (`OwnerSet`); fleet:owner changes it within manage reach, a retired owner's ships fall to argo (`OwnerChanged`); questions, trouble and gates go to the owner, its ship reaches the ships it owns; no process beyond that until a need shows.
- [0046](0046-scope-catalogue.md) **Scopes.** `<namespace>:<action>`; core namespaces messages, fleet, crew, labels, scopes; held by a ship or carried in an account token; the catalogue with each scope's where (send, read or manage reach, identity, ownership, assignment), with fleet:person, fleet:owner, fleet:explain, fleet:connect and labels:any where argo's alone jobs were; granting only what the granter holds or its own namespace, at commission or live with scopes:grant (ScopesChanged); a plugin declares one namespace for good (ScopesDeclared) and enforces its scopes; no rights travel with a message.
- [0047](0047-discovery-and-statements.md) **Discovery and statements.** Any ship with messages:send asks which ships and types it can send to now (name, type, status, statement; no rules, nothing recorded); a statement is a summary plus capabilities on MCP's tool fields with content types, and for the gateway a wait, a deadline and a repeatable mark, stated by the crew on the lease, at most 64 KB, versioned, the commission note as default, pulled never pushed, read by the ships that can send to it and, in the ship read, by fleet:read within read reach.
- [0048](0048-mcp-and-a2a.md) **MCP and A2A.** Statements borrow the agent card's and MCP's field names now; the end state is speaking both protocols in both directions through a gateway beside core, designed starting now.
- [0049](0049-release-trains.md) **Release trains, one repository each.** core (common, core, console), the trierarch (with the aeolus plugin and the session image), squadrons, the trierarch plugin and the gateway; 0.27.1 the last shared version, 0.28.0 each train's first; each non-core package checks a minimum core version at start (docs/compatibility.md).
- [0050](0050-domain-language.md) **Domain language.** One meaning per term, defined in the blueprint; account only a human's in an organisation (pagasae), an IdP login an identity; owner only a ship's, a label has a definer, the app admin manages the application, a fleet manager one fleet; session only an agent run, a human logs in with a sign-in; connect only argo connecting a plugin, an account is linked to a person ship or a trierarch's app ship; role only a squadron member's; no operator account, core's email and password are argo's own sign-in; organisation pagasae's tenant, the fleet core's; kinds by lifecycle (operator, viewer, person, agent, app, plugin), the plugin read a built-in rule for kind plugin; the viewer stays; outside party an approved outside MCP server or client, or A2A agent or client; a trierarch runs on a computer, never a machine.
- [0051](0051-organisation.md) **Organisation.** pagasae's tenant: accounts (by email, active or disabled, one email in several organisations each its own), groups, fleets, later its directory; the organisation admin's right sits on the account, the first account holds it, the last cannot lose it, and it never implies fleet scopes; a fleet's fleet manager holds every scope it offers, and deleting it requires naming a new one in one transaction; the app admin manages the application and all fleets; sign-up creates the organisation, its first account and its first fleet; pagasae is no ship: it signs account tokens and acts as the installation; contractors get an account, no guests.
- [0052](0052-groups.md) **Groups and an account's rights.** A group gives scopes and reach per fleet; an account may also have rights of its own (the fleet manager holds every scope, 0051), its page in pagasae showing the aggregate; rights ride in the account token, a change landing at the next one; the installation defines `group`, declares each group's rules and one default send rule `group=#` to `group=#` (0034's `#`: the same value on both sides); a person ship, owning itself, only to message or own, its account crewing and releasing it through its app, never recommissioned.
- [0053](0053-nothing-is-argos-alone.md) **Nothing is argo's alone.** Every argo job is a scope any actor can hold (fleet:person, fleet:owner, fleet:explain, fleet:connect, labels:any, fleet:network for the rules); grants, owner changes and manage calls checked on the target's manage reach; plugin pages check the actor's scopes; a commission gives only scopes held and labels defined or carried.
- [0054](0054-sign-in.md) **Sign-in through pagasae.** pagasae signs every account in (sign-in link; once a directory is connected, identity, with the link kept only for accounts allowed as argo); the gateway's one address finds the fleets an account has rights in and calls with its account token, crewing the person ship for messaging, with a basic page of its own; one sign-in for every app, the shared cookie each app's server gets account tokens from; the console signs accounts in as themselves; allowed accounts sign in as argo by a ticket naming them; argo's own sign-in where no pagasae runs, not an account.
- [0055](0055-leavers.md) **Leavers and their computers.** Disabling an account cuts off its tokens, ends its sign-ins and releases its person ships and the trierarchs they own, every ship staying; a trierarch on a human's computer joins for their account, owned by its person ship, and adding one takes `trierarch:join`, a scope the trierarch plugin declares, checked on whoever adds it; releasing a trierarch releases the leases it crewed.
- [0056](0056-outside-parties.md) **Outside parties: requests and owner.** An outside party is an approved outside MCP server or client, or A2A agent or client; approving is a gateway scope any actor may hold; the proxy ship's owner is core's alone; one list of pending requests (an outside client's authorize request, asked only by a signed-in account of the fleet, a person's request for a server), kept 7 days (Thomas); the gateway asks its owner, a person ship, by the application-owner rule; the requester sees theirs under Your requests, approvers all on the overview; an approver grants only scopes it holds; fleet:owner, scopes:grant and fleet:manage change the owner, change the scopes and retire it; the client connects again, the person gets a message; outside parties are a switch per fleet, off by default, turned by fleet:network with a warning to confirm on an open network.
- [0057](0057-actors.md) **Actors.** What sends or receives is a ship; every call is authorised for an actor (a ship, an account by its token from a header or the console's cookie, the installation) by scopes and reach, one catalogue and one check, and every event names it, an account by id only; an agent ship can hold any scope any actor holds; a human acts as their account; argo is the fail-safe, where a failure becomes visible and the way out, never a normal path.
- [0058](0058-pagasae-core-link.md) **pagasae and core.** Core trusts pagasae's keys (unset: no accounts); an account token for one account in one fleet carries its id, scopes, group values, person ship and whether it is allowed as argo (alone it reads who holds argo), 10 minutes; presented by plugin pages, the gateway and the console (an httpOnly cookie core sets, changes origin-checked); checked on every call (signature, issuer, fleet, end); a pushed cut-off for leavers; pagasae down stops new tokens, not messaging; no email in core.
- [0059](0059-verified-facts.md) **Verified facts.** A fact an actor checked about a ship, stored as written and naming the writer, a claim core never checks; written whole per writer and ship by any actor holding fleet:verify within manage reach; one shape in common (a check from a closed list, its value, an issuer for an OAuth subject), never a URL path or credential; kept with the ship until withdrawn or the writer or ship retires; shown in discovery beside the statement; person ships left out.
- [0060](0060-a2a-through-the-gateway.md) **A2A through the gateway.** An approver adds an outside A2A client on the gateway's page (name, owner, scopes), commissioning an `a2a-client` proxy ship and showing a bearer once; cards at `/gw/a2a/<alias>`, the alias derived, the public card with no summary or skills and `extendedAgentCard: true`, the extended card the statement from `discover` as the caller's proxy ship, an unknown and an unreachable alias the same error; the party's detail lists the card addresses its proxy ship reaches now; one switch for MCP and A2A; an inbound message calls the first capability whose first input mode is its content type (one text part as text, one data part as JSON, else the whole message as `application/a2a+json`); no cancellation, a follow-up asks to stop; an outside agent repeatable unless an approver marks it; AUTH_REQUIRED a reply to the sender, then handled, the owner notified once notifications land; `@a2a-js/sdk` pinned behind ports with the gateway's call store, on Fastify beside `/mcp`.
