# 0035 Networking plugin: who supplies the rules, and what holds while it is unavailable

- A networking plugin is a ship of the fleet, connected as squadrons and the trierarch plugin are (0017, 0030), with `fleet:network`. It registers with `fleet.registerNetworkPlugin`, declaring `whileUnavailable` (`block-all`, `open-all` or `keep-latest`) and `notRespondingAfterSeconds` (60 to 86400). Its ship becomes the one owner of the fleet's rules, as a label has one: while it is registered, only it sets them (0034's `fleet.setNetworkRules`), argo included, and any other ship is refused (`NOT_THE_NETWORK_PLUGIN`, FORBIDDEN). One plugin a fleet: another ship's registration is refused (`NETWORK_PLUGIN_REGISTERED`, CONFLICT); the plugin registering again replaces what it declared.
- Registering leaves the rules as they are until the plugin supplies its own. Unregistering (`fleet.unregisterNetworkPlugin`, the plugin's own ship only, as when it is switched off or deleted for a fleet) and retiring the plugin's ship both take the rules with it: no plugin is all-to-all. Each change moves the settings version and writes its event (`NetworkPluginRegistered`, `NetworkPluginUnregistered`), under the exclusive settings lock of 0034.
- The plugin is unavailable while its ship holds no lease, or while it is not responding: its lease's last seen (every call its crew makes marks it) is older than `notRespondingAfterSeconds`. Judged at each send, in its unit of work, from the lease read without a lock. Nothing ends or expires the lease, and there is no heartbeat call and no timer: the plugin's next call makes it available again. This is the one thing that acts on last seen.
- While it is unavailable, its declaration replaces its rules for that send: `block-all` leaves only 0034's fixed exceptions, `open-all` none (every send goes through), `keep-latest` the rules it supplied last. A refusal then also records what was declared (`whilePluginUnavailable`: `block-all` or `keep-latest`; null for a refusal by the rules themselves).

Why: design 9 and 13 on #260. Unavailable must be something the server sees at send time, since sends never call the plugin. A plugin process, like squadrons, keeps calling receive, so its last seen stays fresh while it runs. One owner keeps the rules the console shows the rules in force. Unavailable (the plugin's choice) differs from no plugin (all-to-all).

Rejected: unavailable as no lease only (a crashed process keeps its lease); a refresh or heartbeat call (0010 rejected heartbeats, and last seen already says it); the plugin declaring itself unavailable (a crashed process says nothing); ping and pong (argo's manual check, no timeout); switching off as unavailable (off is no plugin); anyone with `fleet:network` setting rules beside the plugin (the editor would show rules not in force).
