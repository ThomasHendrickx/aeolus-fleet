# 0036 The networking plugin package: argo's rules, supplied whole

- `@aeolus-fleet/networking-plugin` is the first networking plugin (design 13 on #260): optional, its own package and process beside squadrons, a ship of each fleet it serves (`fleet:read`, `fleet:network`), connected as squadrons and the trierarch plugin are (0017, 0030: the console commissions its ship and hands the secret over, server to server) and switched per fleet as squadrons is (0021). Aeolus knows nothing about it beyond its ship and the networking plugin calls (0035).
- Its own small database holds per fleet the connection, the switch and the network: the rules, the whole list or none for all-to-all, and what it declares for while it is unavailable (`whileUnavailable`, `notRespondingAfterSeconds`). Argo sets both in the console; until argo does, it declares `keep-latest` after 300 seconds. Only argo sees and edits them: a session without `fleet:network`, a viewer's, is refused (FORBIDDEN).
- It supplies a fleet on every change and on reconnect: registers with what argo declared, then sets the whole list (0034). Connecting, a change of the rules or the declaration, switching on, and every start supply it at once. Switching off unregisters, and the fleet is all-to-all; its own rules stay for when it is on again. A supply the fleet refuses is tried again on a timer; supplies of one fleet run one after another, so an older list never lands after a newer one.
- Rules over 0034's limits are refused before they are kept, so a list the fleet would refuse is never supplied again and again.
- A delete unregisters from the fleet first. While the fleet does not answer, the delete is refused (BAD_GATEWAY) and forgets nothing, so the hosting service retries it; a fleet that says the crew token no longer crews or the ship is not the plugin has nothing left to unregister.
- Its ship receives as long as its process runs, which keeps its last seen fresh (0035), and acknowledges every delivery on receipt, acting on none.

Why: the rules exist only through a plugin (0034, 0035), so the editor shows the rules in force; the fleet keeps only the last list supplied, and the plugin holds the source. A fleet must never be left with a plugin nobody can unregister.

Rejected: importing rules already on the server at first connect (a plugin always starts from none); a declaration fixed in the plugin's configuration for every fleet (argo's per fleet); the rules readable by a viewer; a delete that forgets regardless of the fleet; supplying only what changed (the fleet takes the whole list).
