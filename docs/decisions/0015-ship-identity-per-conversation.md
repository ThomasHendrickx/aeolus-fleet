# 0015 Ship identity per conversation, and per folder with the plugin

- `register(shipId, secret, location)` returns a crew token `aeolus_ct_v1_<random>`, stored hashed with the lease.
- Every later ship call carries the crew token: MCP tool argument; tRPC and REST header. The secret is used only to register.
- The MCP connection carries no ship credential. Failed `register` attempts are rate-limited per client address; successful ones never are.
- Crew token ends with the lease (release, deregister, retire, `argo` takeover).
- A Claude Code or Codex session with the Aeolus Fleet plugin keeps its crew token in an identity file per working folder: fleet URL, ship id, ship name, crew token, never the secret. One ship per folder; a worktree is its own folder. `/clear` and a restart keep crewing the ship from that file, without a new `register`.
- The identity files live in `~/.aeolus/crews/<claude-code|codex>/`, one folder per harness, beside `~/.aeolus/trierarch/`, never in the plugin's data folder. The trierarch derives the same path. Identities an older plugin kept in `<plugin data>/ships/` move there once, at the next session start, and a link at the old place keeps sessions on an older plugin working. Codex's workspace-write sandbox lists the harness's folder as writable (plugin README).
- With the plugin, every fleet call goes through its scripts over REST: `register` writes the crew token into the identity file, and every later call reads it there. The model never sees the token.
- A chat with no shell (a claude.ai connector, ChatGPT) crewing an agent ship passes the crew token as a tool argument on core's `/mcp`, so it lands in that chat's transcript and the model's context: an accepted risk. A person never crews a ship that way: they reach their person ship through the gateway, signed in through pagasae, and never see a crew token (0054).

Why: A connection's headers are shared by every conversation using it; a secret there makes all of them one ship. A session's id changes on `/clear`; its folder does not. A token the model passes lands in every transcript; a script that reads it from the file keeps it out. A chat with no shell has no such script, and whether a chat client keeps an MCP session per conversation is unknown, so binding the ship to it could make its conversations one ship; the risk is accepted for agent ships, and people get the gateway (Thomas, #175). Claude Code deletes a plugin's data folder when the plugin is uninstalled or its marketplace removed, and the crew token exists nowhere else (#658).

Rejected: Secret as connection header; OAuth per connector; a connector per ship; identity keyed by session id; binding the ship to the MCP session after one hand-over of the crew token; identities in the plugin's data folder, guarded only by docs that say never to uninstall.
