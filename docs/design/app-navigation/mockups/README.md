# App launcher, fleet button and account button screenshots

Status: round 3 mockups awaiting Thomas’s approval. [Current decisions and proposed interactions](../README.md).

These PNGs are captured from the local [HTML fixture](index.html), with [mockup styles](mockups.css) importing the repository’s shared tokens and fonts. Before reconstructs the inspected navigation source; surrounding content is illustrative, not deployed evidence. After is the round 3 proposal: the app launcher at the start of the bar, then the fleet button and the account button at its end. `App 1` and `App 2` are generic hosted apps, never their pages.

Phone is 375 × 812; desktop is 1440 × 1000. Every primary state has before and after in light and dark. Bridge’s argo and viewer frames show the account-required explanation, not an argo or viewer Bridge session. Its single-app frame shows that Bridge is not installed.

## Capture

From the repository root, with Playwright available:

```sh
node docs/design/app-navigation/mockups/capture.js
```

An isolated Playwright installation can be supplied through `PLAYWRIGHT_MODULE` (its module path); an existing Chromium executable through `CHROMIUM_PATH`. The script starts its own browser, uses only local files, captures reduced motion at 1×, and closes the browser. It checks horizontal overflow, clipped panels, 44 px phone targets, fonts, resource failures, page errors, Escape returning focus to the launcher and to the fleet button, and the arrow keys moving through the fleet list. [Capture results](capture-results.json) records the output. This is documentation capture evidence, not production test coverage.

The prototype simulates loading locally. The eventual shared parts use Base UI’s menu and Sheet behaviour and the app’s actual state and callbacks. No production code or tests are changed.
