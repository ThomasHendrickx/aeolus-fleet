# Apps and fleets screenshots

Status: mockups awaiting Thomas’s approval. [Current decisions and proposed interactions](../README.md).

These PNGs are captured from the local [HTML fixture](index.html), with [mockup styles](mockups.css) importing the repository’s shared tokens and fonts. Before reconstructs the inspected navigation source; surrounding content is illustrative, not deployed evidence. After is the proposal. `App 1` and `App 2` are generic hosted destinations, never their pages.

Phone is 375 × 812; desktop is 1440 × 1000. All primary states have a before and after in light mode, plus the proposed state in dark mode. Bridge’s argo/viewer frames show the account-required destination explanation, not an argo/viewer Bridge session. Its single-app frame shows that Bridge is not installed, not an offered destination.

## Capture

From the repository root, with Playwright available:

```sh
node docs/design/app-navigation/mockups/capture.js
```

An isolated Playwright installation can be supplied through `PLAYWRIGHT_MODULE` (its module path); an existing Chromium executable through `CHROMIUM_PATH`. The script starts its own browser, uses only local files, captures reduced motion at 1×, and closes the browser. It checks horizontal overflow, clipped panels, 44 px phone targets, fonts, resource failures, page errors, and Escape returning focus. [Capture results](capture-results.json) records the output. This is documentation capture evidence, not production test coverage.

The prototype simulates loading locally. The eventual shared part uses Base UI’s full menu and Sheet behavior and the app’s actual state and callbacks. No production code or tests are changed.
