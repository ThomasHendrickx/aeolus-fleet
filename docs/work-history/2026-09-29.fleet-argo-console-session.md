## Goal

A fleet can be initialised, and the operator can sign in to the console as the ship `argo`. Every call is authorised by scopes stored on the server.

## Build

- Schema, in a new migration: remove the operator account tables; add `console_sessions`; add kind (`operator` or `agent`) and scopes to ships; add the event shape (type, time, actor ship or system, ship, message and delivery it concerns, small details); add the lease location (`DEVICE`, `CLOUD`, `SERVER`, `OTHER` plus description); add optional in-reply-to and resend-of on messages; add the dismissed delivery state and a read date. Retire the `opr_` prefix in common.
- Scopes: `messages:send`, `messages:receive`, `fleet:read`, `fleet:manage`. A secret or session lookup returns ship, fleet, kind and scopes in one query (the one lookup not scoped by fleet). The API checks the procedure's required scope before any use case runs.
- Fleet init: a server command (`npm run fleet:init -w @aeolus-fleet/server`) that creates the fleet and `argo` (kind `operator`, all scopes) and prints `argo`'s secret once. It refuses to run when a fleet already exists.
- Replace argo's secret: a server command that invalidates the old secret, prints a new one once, and ends every console session.
- Console sign-in: exchange `argo`'s secret for a random session token, stored as SHA-256, sent as an httpOnly secure SameSite cookie, valid 30 days after last use. Signing in ends the previous console session and takes `argo`'s lease over; its in-flight deliveries return to pending; the secret stays valid. The console session's lease location is `OTHER` with the description `web console`. Rate-limit sign-in.
- Sign-out ends the session and releases `argo`'s lease.
- `argo` can never be retired, released or renamed, and the name `argo` is reserved. Enforce it in the domain; commissioning comes in slice 2, but the rule and its tests belong here.
- Events: fleet initialised, ship commissioned (argo), ship claimed, lease revoked, credential revoked, each in the same transaction as its change.
- Health: server `/health` reports server up and database reachable; web `/health` reports web up and the server's health. Neither says anything about fleets. `system.ping` requires `fleet:read` or is removed; say which you chose and why.
- Web: a sign-in page (paste the secret), a signed-in placeholder page, sign-out. Unstyled; the console design comes later.
- Release: `release.yml` also tags the released commit `v<version>` (needs `contents: write`).

## Questions asked and answered

Asked in the PR draft before any code; Thomas answered:

- **Fleet name at init:** a required argument, `--name`.
- **argo's type:** `operator`, the same word as its kind. A message to type `operator` reaches argo.
- **Replacing the secret and the lease:** the lease ends with the console sessions (`LeaseRevoked`, deliveries in flight back to pending), as with sign-out.

## Key decisions

Not dictated by the docs:

- **`system.ping` stays, behind `fleet:read`.** The signed-in placeholder uses it to prove an authorised browser call reaches the database, and it gives the scope check a real procedure to refuse. It still counts every fleet in the installation (see Noticed, not done).
- **Context boundaries.** Each context's `index.ts` is its published surface. Identity uses registry's lease operations and `findOperatorShip`; registry's fleet init uses identity's `issueShipSecret`. Registry returns deliveries through its own `InFlightDeliveries` port, so core never touches Messaging.
- **Actors.** Server commands write events as the system; console actions as `argo`.
- **Event details.** A flat JSON object. `LeaseRevoked` carries the lease id, the reason (`takenOver`, `signedOut`, `secretReplaced`) and how many deliveries returned; `ShipClaimed` carries the lease id and location.
- **Location.** `OTHER` needs a description of 1 to 100 characters; the other kinds take none. Enforced in the domain and by a check constraint.
- **Fleet name.** Trimmed, 1 to 100 characters.
- **Secrets and tokens.** `aeolus_sk_v1_` plus 32 random bytes, base64url; the session token is 32 random bytes, no prefix. Both stored as SHA-256 hex.
- **The session and its lease.** A console session records the lease it holds; sign-out ends only that lease, so signing out an old session never ends the lease of the one that took over. An expired session keeps the lease until the next sign-in or secret replacement ends it.
- **Cookie.** `aeolus_session`, `HttpOnly; Secure; SameSite=Strict; Path=/`, `Max-Age` up to the session's expiry, renewed on every authorised use because the 30 days count from the last use.
- **Callers.** A bearer secret wins over the cookie, and a wrong one fails without falling back. An agent ship's secret at sign-in is refused with 403. Sign-out always clears the cookie and changes nothing without a live session.
- **argo's credential** is marked claimed on the first sign-in.
- **Rate limit.** 10 sign-in attempts per client address per minute, in memory. `TRUST_PROXY=true` lets the server see client addresses behind Caddy.
- **Locks.** Fleet init takes a transaction advisory lock. Sign-in, sign-out and secret replacement lock a credential, then console sessions, then leases, so they serialise without deadlocks.
- **Database rules.** Check constraints for known scopes, argo as the only operator ship and only ship named `argo`, argo never retired, the location description, and event details as an object. The secret hash is unique across fleets.
- **Health bodies.** Server: `{ server, database }`, 503 when the database is down. Web: `{ web, server, database }`, 503 when anything behind it is down.
- **Sign-in form.** The button stays disabled until React hydrates, and the form posts, so a native submit can never put the secret in a URL.
- **Commands.** Exit 0 done, 1 refused, 2 wrong usage. `argo:replace-secret` acts on the installation's only fleet and refuses to choose between several.
- **End-to-end tests** use the `playwright` library inside Vitest (one runner, part of `npm test`) and `next dev`, because the web build fixes the `/trpc` target at build time. `CHROMIUM_EXECUTABLE_PATH` points at an existing Chromium.
- **Release tag.** A lightweight tag on the checked-out commit, pushed after all three packages are on npm; a version whose tag exists is refused before anything is built.

## Noticed, not done

- The architecture's origin check on cookie requests is not built; `SameSite=Strict` keeps other sites from sending the cookie for now.
- No lint rule yet for "one context imports another only through its `index.ts`".
- `system.ping` counts every fleet in the installation, so with several fleets a `fleet:read` caller would learn how many tenants exist.
- An expired console session leaves argo crewed until the next sign-in or secret replacement; there is no background job.
- Returning deliveries in flight matches on `claimed_by_ship_id`; slice 5 must set it on every claim, direct deliveries included.
- The migration adds `NOT NULL` columns without defaults (`ships.kind`, `leases.location`, `events.details`); it would fail on a database with rows in those tables. No installation has any yet.
- `next dev` writes `AGENTS.md` and `CLAUDE.md` into `packages/web` when it detects an AI agent (it did during these tests). Not committed: commit, ignore or leave them is Thomas's call.
- The commands run from the repository with `tsx` (a dev dependency). The published package builds them to `dist/bin/`, but has no `bin` entry.
- The `Secure` cookie works on `https://` and `http://localhost` only; a plain-HTTP LAN address cannot sign in.
- `docs/architecture.md`'s code structure does not list `src/adapters/http`, `crypto`, `cli`, `src/bin`, `src/wiring.ts` or the root `e2e/`.
- The in-memory rate limiter assumes one server process, as v1 does.
