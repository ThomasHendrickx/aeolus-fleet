## Key decisions

Not dictated by the docs:

- **Argon2id from Node's crypto** (`crypto.argon2`, Node 24.7 and later), no new dependency. Stored in the reference PHC format; parameters are OWASP's baseline (19 MiB, two passes, one lane) and are read back from each hash, so they can change later. Tested against the reference implementation's vector.
- **Email** is trimmed and lowercased when stored and when looked up. Its shape (one @ with something on each side, no whitespace, at most 254 characters) is checked at init only; sign-in takes any email, so a malformed one is just wrong.
- **Password**: 1 to 1024 characters, kept exactly as typed, no strength rules (ADR 0016). Asked twice, hidden, at init and at reset.
- **One refusal** for a wrong email and a wrong password: `WRONG_EMAIL_OR_PASSWORD`, 401, "Wrong email or password". An unknown email still checks a password, so the timing matches too.
- **Password check before the lock**: sign-in finds the account and checks the password outside any unit of work, so no account row or pooled connection waits on Argon2, and parallel attempts on a known email do not queue where unknown ones do. The unit of work then locks the account and refuses when its hash changed meanwhile. A reset locks the same row first, so a sign-in with the old password either ends with the reset or is refused. Lock order: ship, then credential or operator account, then console sessions, then leases.
- **Table**: `operators` (id, fleet_id unique, email unique across the installation, password_hash, created_at). Prisma model `Operator`, domain type `OperatorAccount`.
- **Events**: `FleetInitialised` also names the operator account id. A reset writes the new `OperatorPasswordReset` (Identity, actor system, the operator account id, no ship), added to the blueprint's event table as slice 2 did for its event, then `LeaseRevoked` with reason `passwordReset` for each ended session.
- **argo has no secret**: the migration deletes operator ships' credentials; `bySecret` never returns argo, even for a secret stored for it; `checkCanClaimWithSecret` (FORBIDDEN) is the rule for slice 3's `register`, like the retire, release and rename rules slice 1 added ahead of their use cases. The listing shows argo without a prompt.
- **Commands**: `fleet:init` keeps `--name` as an argument and asks the email and the password twice. `operator:reset-password` takes no arguments and refuses zero or several fleets before asking. Answers are read a line at a time from standard input, so they can be piped; on a terminal, hidden answers are not echoed, each question is readline's prompt so a corrected line keeps it, and no answer is kept in readline's history. Input ending early exits 2; two different passwords exit 1 and change nothing.
- **Cookie domain and console origin**: `COOKIE_DOMAIN` adds `Domain=` to the session cookie, its renewal and its clearing; the examples use the narrowest shared domain, since every host under it receives the cookie. `CONSOLE_ORIGIN` (normalised as a browser sends it: lowercase host, no default port) is the one origin that gets `Access-Control-Allow-Origin` with credentials; preflights allow GET and POST with `content-type`, cached 10 minutes; `Vary: Origin` whenever it is set. Both unset by default: a host-only cookie and no CORS, which is what local development through the Next rewrite needs. SameSite stays Strict: hosts under one domain are the same site.
- **Web**: the sign-in form is an organism with React Hook Form and common's schema; the page only renders it.
- **End to end**: the sign-in test initialises the fleet through the real `fleet:init` command with piped answers.

## Open questions

1. No minimum password length (ADR 0016). Do you want one?
2. The email is lowercased as a whole, local part included. Fine?
3. `OperatorPasswordReset` names no ship. Should it concern argo, so it shows on argo's timeline?
4. The web app still calls `/trpc` on its own origin. A console on another host also needs the server's URL in the browser client and `credentials: 'include'`. Which slice builds that, and is a build-time `NEXT_PUBLIC_` setting acceptable for the published web package?
5. The architecture's security baseline names "an origin check" next to SameSite cookies. Hosts under one domain are the same site, so a page on a sibling host could post a form with the session cookie. Build an origin check for state-changing calls now or later?
