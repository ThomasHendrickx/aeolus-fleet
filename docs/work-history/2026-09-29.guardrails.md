## Key decisions

Not dictated by the docs:

- **"Preceded by" means the commit's parent.** A commit that changes production code must have, as its direct parent in the pull request, a commit whose subject ends in `(red)` and that only adds, modifies or renames test files. Production code is everything under `packages/server/src` and `packages/common/src` except tests and Markdown. A test file is `*.test.ts(x)` or anything in a `test/` or `e2e/` folder. Merge commits are not judged. Commits up to main at `1890538` are exempt, besides the pull request range excluding them anyway. Open question 1.
- **Only in pull requests:** TDD evidence, em dash and work history need a base and a head, so they run on `pull_request`. The other three also run on pushes to main.
- **A use-case file** declares an exported factory named `create<Name>`; a re-export does not count.
- **The core never throws.** Refusals are `Result<T, DomainError<kind>>`. Prisma rolls back only on a throw, so its unit of work throws a private `Refused` inside the transaction and returns the refusal outside it, proven on Postgres. The core rules apply to core tests too.
- **Clock and crypto.** `new Date()` without arguments and `Date()` are refused; `new Date(time)` is not. Crypto means `crypto` or `node:crypto` imports, the `crypto` global and `globalThis.crypto`.
- **Context boundaries.** Registry, identity and messaging reach another context only through `<context>/public.js`; `shared` is open to all. The surfaces kept their exports.
- **Prisma and pg** means `@prisma/*`, `pg` and `pg-*`, in every package, tests included; test databases are now created through the Prisma client. The `prisma` CLI package stays allowed in `prisma.config.ts`.
- **Web layers.** Pages in `app/` sit above templates. "No tRPC" means `@trpc/*`, `@aeolus-fleet/server` and `lib/trpc`.
- **Plugins.** `eslint-plugin-jsx-a11y` and `eslint-plugin-react` declare ESLint 9 at most, so npm refuses them next to ESLint 10. `eslint-plugin-jsx-a11y-x` (a fork that keeps the same recommended rules) and `eslint-plugin-react-x` (`no-array-index-key`) support ESLint 10. Kebab-case comes from `eslint-plugin-check-file`, which checks the name before the first dot, so `postgres.global-setup.ts` and `*.test.ts` pass.
- **Default exports** are allowed where Next.js reads them (page, layout, loading, error, not-found, global-error, template, default) and in tool configs (`*.config.{js,ts}`), whose tools read only a default export. The Vitest global setup uses its named `setup` export instead.
- **Boolean names** are checked on variables, parameters, class and type properties, parameter properties and accessors, and must continue in PascalCase after the prefix (`island` fails). Object literal properties are not checked, because they often follow a library's option names (`trustProxy`, `httpOnly`). A destructured name is checked where it is declared.
- **Module mocks** means `vi.mock` and `vi.doMock`.
- **Exhaustive switches** keep typescript-eslint's default: a `default` branch does not excuse a missing union member.
- **Rows are outside data.** The Prisma row mappers parse rows with Zod schemas built from `idSchema`, `shipKindSchema`, `scopeSchema` and `locationKindSchema`.
- **The lint tests** live in `lint/`, one file per area, each with one ESLint instance: typescript-eslint keeps one project service per process.

## Open questions

Keep it strict, or let a `refactor(...)` commit follow a passing green commit?
2. **Tool config default exports.** The prompt names Next.js only; `vitest.config.ts`, `eslint.config.js` and `prisma.config.ts` cannot work without a default export, so they are allowed. Agreed?
3. **`vi.fn` and call assertions.** The TDD skill says "assert outcomes and stored state, not calls", and the command tests use `vi.fn` with `toHaveBeenCalledWith`. Only `vi.mock` is banned. Ban `vi.fn` and `vi.spyOn` too?
