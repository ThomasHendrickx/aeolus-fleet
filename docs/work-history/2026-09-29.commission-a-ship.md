## Goal

The operator (argo) can commission an agent ship and hand out its starting prompt.

## Build

- Commission ship (requires `fleet:manage`): name, type, optional note.
  - Name is a handle: lowercase letters, digits, hyphens, max 48; unique among non-retired ships in the fleet; reusable after retirement; `argo` reserved.
  - Type is a free label with the same handle rules.
  - Kind `agent`, scopes `messages:send` and `messages:receive`, stored with the ship at creation.
  - The ship starts in Awaiting crew. Commissioning also issues the first starting prompt (blueprint, "Launch a ship" step 2).
- Get starting prompt (requires `fleet:manage`): only while the ship awaits crew.
  - Creates a new `aeolus_sk_v1_<random>` secret, stored as SHA-256, and invalidates any earlier one: at most one valid secret per ship.
  - Returns the prompt once; the secret is never readable again.
  - The ship exposes whether an unclaimed prompt is outstanding and when it was issued, so the console can ask for confirmation before replacing it (the confirmation itself is a UI concern).
- Placeholder prompt text: server URL, ship id, secret. The real text is drafted in slice 8.
- List the fleet (requires `fleet:read`): per ship its name, type, status, and prompt state (issued when, claimed or not). argo included.
- Events in the same transaction: ship commissioned, starting prompt issued, credential revoked (when a prompt replaces an earlier one).
- Web: a bare, unstyled page (signed in as argo) listing the fleet, a commission form, and a "get starting prompt" action that shows the prompt once with a copy button and asks for confirmation when an unclaimed prompt is still out.
